# Ahmad Abdullah — Portfolio ("Darkroom")

A React portfolio that behaves like a design tool: the site is a Photoshop-style
workspace (tool palette, rulers, Layers panel, status bar) with each section
drawn as a paper artboard carrying print crop marks.

```bash
npm install
npm run dev       # http://localhost:5173
npm run build     # → dist/
npm run images    # rebuild web images from media-source/ (see below)
```

## Stack

- **Vite + React 19 + React Router 7**
- **GSAP** (ScrollTrigger, Draggable, Inertia) for scroll choreography, pinned scenes and dragging
- **Lenis** smooth scrolling, driven by GSAP's ticker
- **Motion** for component transitions (page changes, filters, menus, the History panel)
- **CSS Modules** per component, plus global design tokens in `src/styles/tokens.css`
- Self-hosted fonts: Bricolage Grotesque, Fraunces, IBM Plex Mono

## Editing content

Everything is in `src/data/portfolioData.js`:

- **Testimonials** — add real reviews to `testimonials`; the section appears automatically.
- **Case studies** — `caseStudies`. The brief / approach / result text is a **draft**
  written from the images; replace it with the real story.
- **Fiverr link** — `site.fiverrUrl`. **Social links** — `site.social` (placeholders).

## Contact form (messages straight to your inbox)

The brief form on /contact sends through [Web3Forms](https://web3forms.com) —
no backend, and visitors never leave the page.

1. Go to web3forms.com, enter `official.ahmedabdullah@gmail.com`, and copy the
   access key they email you.
2. Create `.env.local` (see `.env.example`):
   `VITE_WEB3FORMS_KEY=your-key`
3. Restart `npm run dev`. On your host (Vercel/Netlify), add the same variable
   in the project's environment settings and redeploy.

Without a key the form falls back to opening the visitor's mail app.

## Client reviews (live, approve-first)

Clients post a star rating and review on the site, either from "Leave a review"
on the homepage or from `/review`. Reviews are stored in
[Supabase](https://supabase.com) and appear on the site only after you approve
them. Approved reviews show up for every visitor straight away, with no reload.
They appear in the homepage summary, ticker and cards, and on the matching
case study.

1. Create a free Supabase project. In **SQL Editor**, paste and run
   `supabase/reviews.sql`. This creates the table, the security rules, realtime
   updates and the photo bucket.
2. In **Project Settings → API**, copy the Project URL and the `anon` public
   key into `.env.local`:
   `VITE_SUPABASE_URL=...` and `VITE_SUPABASE_ANON_KEY=...`
3. Add the same two variables on your host and redeploy. They are baked in at
   build time.
4. **To approve a review:** go to Table Editor → `reviews`, tick `approved` on
   the row and save. It appears live. Delete a row to remove a review.
5. **To ask a client for a review:** send them a prefilled link, e.g.
   `/review?project=codespark-solutions&service=logo-design`.

The reviews section stays hidden until these variables are set. To try the
whole flow without Supabase, run `npm run dev:mock`. Test reviews then
"approve" themselves after a few seconds. Mock mode never ends up in a build.

## Images

Full-resolution originals live in `media-source/projects/<category>/` (git-ignored —
some are hundreds of MB). `npm run images` writes WebP versions (≤2000px full,
≤760px thumbnails) into `src/assets/projects/`. To add work: drop files into a
category folder, run `npm run images`. A new folder also needs an entry in
`archiveCategories`.

## Design rules this follows

- Motion has a job: feedback, orientation, focus or continuity (Val Head).
- Disney principles in UI: anticipation (squash on press, typing dots), follow-through
  (springy release), slow in/out easing, staging (one focus per artboard).
- Laws of UX: big targets (Fitts), one decision at a time — the pricing lever and
  History panel (Hick), responses under 400ms (Doherty), one standout per view (Von Restorff),
  a small delight near the end — the easter egg (Peak–End).
- Everything works without animation: `prefers-reduced-motion` turns off smooth scroll,
  pinning, the custom cursor and the preloader, and shows finished states.

## Development rules

- **The cursor is always the top layer.** Nothing may cover the custom cursor:
  not modals, popups, toasts, overlays, the preloader or the easter egg.
  - Stacking uses the `--z-*` tokens in `src/styles/tokens.css`. Never write a
    raw z-index at or above `--z-cursor` (the maximum, 2147483647); give new
    overlays a token below it.
  - Modals and popups use native `<dialog>` (`showModal()`) or the Popover API.
    These render in the browser's top layer, which beats any z-index. The
    cursor (`components/chrome/Cursor.jsx`) is a manual popover that
    re-promotes itself whenever a dialog or popover opens. Don't build modals
    another way (for example a portal with a huge z-index) without keeping
    this guarantee.
  - When adding a modal or popup, check with a mouse that the cursor is
    visible above it and above its backdrop.
